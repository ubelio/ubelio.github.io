Overview

Where the Microsoft Learn MCP mission consumes an existing hosted MCP server, this mission builds one from scratch and deploys it to the cloud. Using the Azure Developer CLI (azd), a custom MCP server is deployed as a publicly accessible Azure resource and then connected to a Copilot Studio agent as a callable tool. This is the complete end-to-end pattern for teams that need proprietary MCP integrations — connecting internal systems, private APIs, or custom business logic to Copilot Studio agents without relying on prebuilt connectors or certified third-party servers. The mission also establishes how MCP servers surface inside Copilot Studio via the existing connector infrastructure, answering the practical question of when to use MCP versus standard connectors.

What I Built

  • Built a custom MCP server locally and deployed it to Azure as a publicly accessible endpoint using Azure Developer CLI (azd up).
  • Connected the custom-deployed MCP server to a Copilot Studio agent as a callable tool and verified end-to-end tool invocation from the agent conversation.
  • Explored how MCP servers surface in Copilot Studio through the platform's existing connector infrastructure, clarifying the relationship between MCP and traditional connectors and when each approach is appropriate.
  • Decommissioned the Azure deployment post-lab using azd down, following least-privilege and cost hygiene practices to avoid leaving public resources running unnecessarily.

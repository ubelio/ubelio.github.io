Overview

Shared Access Signature URIs provide time-bound, permission-scoped access to Azure Storage without exposing account keys. In this lab, I created a blob container, uploaded sample files, generated a SAS token scoped to Read and List permissions only over HTTPS, and validated the token's behavior using Azure Storage Explorer on a lab VM — confirming that list and read operations succeeded while a delete attempt was blocked, demonstrating effective least-privilege access control via SAS URI.

What I Did

  • Connected to the lab VM via Remote Desktop and opened Azure Storage Explorer, selecting Shared Access Signature URL as the connection method
  • Created a blob container (container1) in the pre-provisioned storage account and uploaded two sample text files
  • Enabled storage account key access under Configuration, then navigated to Shared Access Signature settings
  • Generated a SAS token scoped to Blob service only, with Service, Container, and Object resource types, Read and List permissions only, and HTTPS protocol enforcement
  • Copied the Blob service SAS URL and pasted it into Azure Storage Explorer on the lab VM, connecting as MyLabCnx
  • Expanded the connection and opened container1, confirming both uploaded files were visible — validating list access
  • Attempted to delete a file and confirmed the action failed in the Activities pane — validating that the SAS token's Read and List-only permissions correctly blocked write and delete operations

Overview

By default, Azure Blob Storage is accessible over the public internet. In this lab, I disabled public network access on a storage account and replaced it with a private endpoint, ensuring all traffic between a virtual machine and the blob service travels entirely within the virtual network. I used DNS lookups before and after configuration to confirm the storage account's hostname shifted from resolving to a public IP to resolving to a private IP within the virtual network — demonstrating the full Private Link and private DNS zone integration flow.

What I Did

  • Reviewed the storage account's network settings and confirmed public access was enabled, then noted the two subnets on lab-vnet: vm-subnet and private-endpoint-subnet
  • Connected to lab-vm via SSH and ran an nslookup against the storage account's blob endpoint, confirming it resolved to a public IP address
  • Disabled public network access on the storage account, blocking all public internet access to blob storage
  • Created a private endpoint (pe-blob-storage) scoped to the blob sub-resource of the storage account, placed in the private-endpoint-subnet subnet of lab-vnet
  • Enabled private DNS zone integration during endpoint creation, which provisioned the privatelink.blob.core.windows.net zone and linked it to lab-vnet
  • Reviewed the private DNS zone record set confirming the storage account name resolved to a private IP in the private-endpoint-subnet range
  • Confirmed the virtual network link to lab-vnet was in place, allowing VMs on that network to use the private DNS zone for resolution
  • Re-ran the nslookup from lab-vm and confirmed the storage account hostname now resolved to a private IP address starting with 10.0.1, verifying all traffic stays within the virtual network

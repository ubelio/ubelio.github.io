Overview

Azure Container Registry (ACR) and App Service together provide a fully managed pipeline for hosting containerized web applications without managing infrastructure. In this lab, I was given a Dockerfile for a custom JavaScript application and tasked with building and hosting it following the company mandate that all container images be stored in ACR. I used Azure Cloud Shell to create a container registry, cloned the application source, built and pushed the image using ACR Tasks, and deployed it as an Azure App Service web app backed by the private registry.

What I Did

  • Opened Azure Cloud Shell in Bash mode and mounted an existing storage account with a new file share
  • Set shell variables for the ACR name and resource group to use consistently across commands
  • Created a new Azure Container Registry with Basic SKU and admin credentials enabled: 
    az acr create --resource-group $RG --name $ACR --sku Basic --admin-enabled true
  • Cloned the js-docker branch of the ACloudGuru AZ-104 GitHub repository into the Cloud Shell clouddrive directory
  • Built the Docker image and pushed it directly to ACR using ACR Tasks, which builds in the cloud without requiring a local Docker daemon: 
    az acr build --image js-docker:v1 --registry $ACR --file Dockerfile .
  • Verified the container registry and js-docker repository appeared in the Azure portal under All resources
  • Created a new App Service Web App with Container as the publish type, Standard S1 pricing plan, and Azure Container Registry as the image source with Admin credentials authentication
  • Loaded the deployed web app URL in the browser after allowing 2–3 minutes for initialization, confirming the containerized application was running successfully

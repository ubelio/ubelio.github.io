Overview

VNet peering connects Azure virtual networks so resources can communicate privately across network boundaries — a foundational pattern for Hub and Spoke architectures and cross-region or cross-subscription deployments. In this lab, I configured peering between three virtual networks, deployed a VPN Gateway on the hub VNet to enable gateway transit, peered a spoke VNet to the hub with gateway transit enabled, and validated connectivity end-to-end using ping from a Linux VM's serial console.

What I Did

  • Added a GatewaySubnet to vnet2 and deployed a VPN Gateway (vpngw, VpnGw1AZ SKU) with a new public IP (vpngwip), waiting for the 20–45 minute deployment to complete
  • Created bidirectional VNet peering between vnet2 and vnet1, adding both link names (vnet1-to-vnet2 and vnet2-to-vnet1) in a single peering operation and confirming Connected status
  • Validated vnet2-to-vnet1 peering by connecting to vm2 via Serial Console, authenticating, and running ping 10.1.1.4 — confirmed 0% packet loss
  • Created bidirectional VNet peering between vnet2 and vnet3, enabling "Use remote gateway" on vnet3's side and "Allow gateway transit" on vnet2's side to route vnet3 traffic through the VPN gateway on vnet2
  • Validated vnet2-to-vnet3 peering from vm2's Serial Console by running ping 10.3.3.4 — confirmed 0% packet loss, verifying gateway transit connectivity

Overview

Diagnosing and remediating Azure VM issues requires systematic elimination — confirming platform health first, then isolating the problem to OS or network configuration. In this lab, I was given a VM reported as inaccessible with a low-disk warning. I confirmed the VM was running and the guest OS was healthy via Boot Diagnostics, identified a misconfigured NSG rule as the access blocker, corrected it to restore RDP connectivity, then stopped and deallocated the VM to resize the OS disk from 128 GiB to 256 GiB and extended the volume inside Windows — completing a full troubleshooting and remediation cycle.

What I Did

  • Confirmed the VM (lab-vm) was in Running status and reviewed Boot Diagnostics, which showed a Windows sign-in screen confirming the guest OS started successfully
  • Attempted a Bastion connection and confirmed it failed with a Connection Error — isolating the issue to network configuration rather than the platform or OS
  • Navigated to Network Settings and located the inbound NSG rule named Allow-RDP targeting TCP port 3389 — confirmed its Action was set to Deny instead of Allow
  • Changed the Allow-RDP rule's Action from Deny to Allow and saved — restored RDP connectivity confirmed by a successful Bastion connection
  • Stopped and deallocated the VM to meet the prerequisite for disk resizing
  • Navigated to the OS disk (lab-vm-osdisk) and changed the disk size from 128 GiB to 256 GiB under Size + performance, then saved and waited for the resize to complete
  • Restarted the VM, connected via Bastion, and opened Disk Management through Computer Management in Server Manager
  • Used Extend Volume on the C: drive to claim all unallocated space, confirming the C: drive now reflected the full 256 GiB capacity

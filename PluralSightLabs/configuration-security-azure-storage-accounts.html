Overview

Azure Storage accounts offer multiple layers of access control — from account-level access keys to scoped Shared Access Signatures and Stored Access Policies. In this lab, I created and configured a storage account, explored replication and access tier options, and worked through progressively more granular access control scenarios using Azure Storage Explorer on a Windows VM. I demonstrated how access keys grant full control, how rotating keys immediately revokes existing connections, how SAS tokens can scope permissions to specific services and resource types, and how Stored Access Policies enable centralized revocation of SAS tokens without key rotation.

What I Did

  • Created a storage account with LRS redundancy, then connected to a lab VM via Remote Desktop and launched Azure Storage Explorer
  • Signed in to Azure Storage Explorer using Azure AD, created a blob container named "images", and uploaded image files
  • Connected to the storage account using an account-level access key, uploaded and downloaded files successfully, then rotated key1 to confirm the key-based connection was immediately revoked
  • Generated a SAS token scoped to Blob service only with Read and List permissions — confirmed access to the container was denied because Container resource type was not included
  • Generated a second SAS adding Container and Object resource types — confirmed list access worked but upload failed due to missing Write permissions
  • Generated a third SAS adding Write, Add, and Create permissions — confirmed file upload succeeded
  • Rotated the access key again to revoke all three SAS connections simultaneously, confirming key rotation as a bulk revocation mechanism
  • Created a Stored Access Policy (Test-SAP) on the images container with all permissions and a defined validity window
  • Generated a container-level SAS linked to the Stored Access Policy via Azure Storage Explorer, confirmed upload and delete operations worked
  • Deleted the Stored Access Policy from the Azure portal and confirmed the SAS connection was immediately revoked on next access — demonstrating centralized SAS revocation without key rotation

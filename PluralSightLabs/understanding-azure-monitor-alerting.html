Overview

Azure Monitor Alerting provides three complementary components for operational awareness and noise management: alert rules that define when to fire, action groups that define who to notify and how, and alert processing rules that suppress or modify alerts during known maintenance windows. In this lab, I configured all three — creating an availability alert rule on a storage account, building an action group with email and webhook notifications, and defining a recurring suppression rule to silence alerts during a weekly VM maintenance window.

What I Did

  • Created an alert rule in Azure Monitor scoped to the lab storage account, using Availability as the signal condition with default thresholds, and set severity to 1 - Error with the name "storage01Unavailable"
  • Created an action group (notifyOfUnavailable, display name: dangerWR) with two notification channels:
    • Email/SMS/Push/Voice notification (notifyofproblem) configured with a fictitious email address and common alert schema enabled
    • Webhook action (notifyUs) with a fictitious URI and common alert schema enabled
  • Created an alert processing rule (updateWindow) scoped to lab-VM with the Suppress notifications action type, configured to run on a recurring weekly schedule every Sunday from 3:00 AM to 5:00 AM — representing a known VM maintenance window where alert noise should be suppressed
  • Added a descriptive rule description: "Virtual Machine is updated every Sunday between 3AM and 5AM"

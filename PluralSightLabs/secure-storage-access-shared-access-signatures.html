Overview

Shared Access Signatures (SAS) provide scoped, time-bound access to Azure Storage resources without exposing account keys or granting broad RBAC roles. In this lab, I was tasked by a security team with demonstrating least-privilege access to sensitive blob data for external contractors. I created a private blob container, uploaded sample datasets, generated a read-only SAS token with an expiry window, and validated the token's permissions using Azure Storage Explorer on a VM — confirming read and list access worked while write and delete operations were blocked.

What I Did

  • Created a private blob container named "contractor-files" in the lab storage account, confirming public access was disabled at the account level
  • Uploaded two sample CSV datasets into the container via Storage Browser in the Azure portal
  • Generated a SAS token for the contractor-files container with Read and List permissions only, using the default 8-hour expiry window
  • Connected to the lab VM via Azure Bastion and opened Azure Storage Explorer
  • Attached to the blob container using the SAS URL via the Shared Access Signature URL connection method
  • Verified read and list access by previewing a CSV file and downloading it successfully
  • Confirmed write and delete were blocked — both a delete attempt and an upload attempt returned insufficient credentials errors, validating the least-privilege scope of the SAS token
